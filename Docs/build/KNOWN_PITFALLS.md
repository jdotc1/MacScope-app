# Known build and native-input pitfalls

- Keep retained Release dependency consumers outside `dependency_cache.py` when that helper belongs to an accepted native source profile. Use `retained_dependency_cache.py` for the new admission route; changing the pinned producer helper invalidates native admission even when no C++ inputs changed. The Release failure before compilation exposed this boundary.

- Staged package snapshots are lists of `[relativePath, kind, fields, digest]`, not dictionaries. A metadata continuation must preserve that schema and all non-device fields; native archive consumers must unpack all four values. Release archive production compares computation/compiler inputs; an app provenance writer that it never invokes is a separate consumer, not a native source input. Covered by the focused synthetic list-admission cases.

Run the short static review once before each focused or integration gate, alongside the producer/consumer audit:

```sh
python3 Scripts/check_known_build_pitfalls.py --base <last-qualified-source-commit>
```

Explicit Swift paths may be supplied instead. The script inspects only those files or changed Swift files, prints candidate `REVIEW` lines, and exits successfully for review findings: a grep-level heuristic cannot prove type ownership or brace scope. Resolve candidates by reading declarations and consumers before building. Missing arguments or Git failures remain command errors. It does not launch Xcode, generate a project, acquire dependencies, or replace affected tests.

| CoreTests are not inherently headless | Several presentation fixtures construct/order native windows. A CLI `xcodebuild test` can therefore violate a GUI stop. Personal-runner CI selects `MACSCOPE_NONWINDOW_CORE_TESTS=1`, inventories window files, excludes every XCTestCase in each file (some files contain multiple suites), and writes `NONWINDOW_TEST_SCOPE.json` with explicit uncovered scope. Never describe this partition as full CoreTests or native GUI acceptance. |
| Synchronous stdin write before a subprocess deadline | Writing a request larger than the ~64 KB pipe buffer to a child that never reads stdin blocks the caller in `write()` before any timeout starts, so the deadline never fires; when the child exits without reading, the write raises SIGPIPE (default action kills the app) or an Objective-C exception from `FileHandle.write(_:)`. (2026-10-11: `PluginExternalExecutionHost.invoke` hung forever with a 1 MB request to a non-reading plugin and died with SIGPIPE when the plugin exited at once.) Start the deadline before the first byte, feed stdin through a non-blocking descriptor with `F_SETNOSIGPIPE` (`PluginStdinFeeder`) or a background writer with throwing/POSIX writes, close stdin after the full write so EOF readers finish, and on timeout close stdin and terminate the child. Manual review: the script has no heuristic for this row; look for `fileHandleForWriting.write(` ahead of a wait loop. |
| CoreTests and app both compile `ReconstructionOperationID` | At an app-owned retrieval/encoder DTO boundary, use `MacScope.ReconstructionOperationID`. Local CoreTests enum values and `.rawValue` strings can be valid; never replace them blindly. The script reports unqualified references only in changed CoreTests files containing an app retrieval query, for manual boundary review. |
| XPC thread signal mask leaks into spawned shell | `posix_spawn` inherits the calling thread mask unless `POSIX_SPAWN_SETSIGMASK` and an explicit empty mask are supplied. Installed broker children self-reported SIGINT/SIGTERM blocked despite process-level `kinfo_proc.p_sigmask` reading zero; correctly routed `kill` returned success without termination. Review spawn attributes and test a blocked launching thread. |
| Staged consumer name differs from independent builder layout | Ghostty VT verified staging publishes ordinary `libghostty-vt.dylib`; the independent builder retains a versioned leaf and governed aliases. On 2026-10-11 three fresh lanes each spent 645–720 s of `prepare` rebuilding SLEIGH and the surface (plus 48–64 s of VT per build) while the shared verified cache already held all three keys. Manual review: a new prebuilt dependency must join the shared cache rather than add another `$TMPDIR` or DerivedData producer. |

| Repeated nested fixture helper names | Anchor edits to the enclosing test/helper, not only `func image`. A replacement landed in a test while its architecture/path parameters belonged to `makeSiblingFocusedSelectorStore`, causing three undefined names and leaving the intended helper inputs unused. Inspect both the declaration and every changed consumer before compiling. |
| Fixture helper integer width | Read the helper signature before assigning new IDs. Single-argument UUID helpers taking `UInt8` accept 0–255; `storeShellUUID` takes `UInt16` and permits larger IDs. The script catches same-file decimal literals above 255 passed to a single-argument UInt8 UUID helper. |
| Private helper inside SwiftUI `body` | Keep private declarations at type scope. A brace-level heuristic reports candidates; comments and string interpolation require manual confirmation. |
| Optional closure result inference | `REAClientWaiter.value()` uses `lock.withLock { () -> Result<Data, Error>? in ... }`. Keep the explicit optional return type when the closure returns both a saved result and nil. The script checks that specific consumer, without constraining unrelated lock closures. |
| Modifier events treated as key events | `NSEvent.flagsChanged` must not read `characters`, `charactersIgnoringModifiers`, or `isARepeat`; these can raise a native exception. Switch on event type before reading key-only properties. The script checks direct `event` accesses in a flagsChanged case; helper calls need manual review and native smoke evidence. |
| Pipe read after waitUntilExit deadlocks above ~64 KB | A child that writes more than the pipe buffer blocks in `write()` and never exits, so waiting before reading hangs forever (2026-10-11: a CoreTests gate hung 4.5 minutes with `lldb` in `__write_nocancel`); with a timeout it becomes a spurious timeout with output truncated at 65,536 bytes. Two pipes read one after the other deadlock the same way when the second fills first, as does an assigned but unread `Pipe()`, and writing large stdin before draining stdout. Drain every pipe concurrently while the child runs: tests use `CoreTestPipeDrain` (create after `run()`, before stdin, join after exit); `FoundationDebuggerProcessRunner` drains on background reads and bounds the join after exit or timeout. Discard output nobody reads with `FileHandle.nullDevice`. The script reports pipe reads preceded in the same function by `waitUntilExit()`, `.wait(timeout:` or an `isRunning` loop, sequential reads of two pipes, and `standardOutput/standardError = Pipe()`. |
| Run-loop spin inside a SwiftUI update aborts in AttributeGraph | Never block or spin the run loop (`waitUntilExit`, `RunLoop.run`) inside SwiftUI view construction, `StateObject` initializers or `body`; do subprocess work off the main thread. `Process.waitUntilExit()` runs the current run loop until the child is reaped; on the main thread inside a graph update that re-enters `NSHostingView.layout` and aborts in `AG::Graph::value_set` (2026-10-11: CoreTests `FocusedPresentationIdentityTests` SIGABRT when the LLDB capability proof, run from `EditorSurfaceView`'s `StateObject` autoclosure, timed out and the runner waited with `waitUntilExit`). Wait on the `terminationHandler` semaphore instead (`FoundationDebuggerProcessRunner.terminateAndReap`), and memoize launch-time probes off the main thread (`DebuggerLLDBProofCache`). The script reports `.waitUntilExit()` and `RunLoop.current/main.run` calls in `MacScope/Features` and `MacScope/Services/Debugger` files; confirm the call cannot run on the main thread. |

| Input-loop liveness guard bypasses admission diagnostics | Preserve initial inactive-session admission before the retry loop: an early `isRunning` return can safely block broker dispatch while silently dropping the user-facing error. Keep stale renderer callbacks silent through the existing surface-aware admission path. Demonstrated by `testStoreRejectsShellInputWithoutActiveSessionBeforeBrokerDispatch` on 2026-10-12. |

| CI selection setup crosses a guarded command or extracted fixture boundary | The Build and test step must begin with the qualifier itself; put literal selector preparation in a prior step. Keep mode-dependent selection recording inside the test-mode branches so extracted Xcode setup fixtures remain independently executable. |

When a gate fails, preserve its exact error and retained project/DerivedData. Fix an in-scope compile or test-fixture defect as part of the authorized deliverable, then use that retained project for one incremental `build-for-testing`/focused retry so remaining compile errors surface together. Add a newly demonstrated pitfall here the same day. Do not start an unrelated warning or toolchain cleanup campaign.

| Fixed-width binary fixture replacement changes the buffer length | `Data.replaceSubrange` permits a differently sized replacement. A 15-byte dyld magic plus two NULs expanded a 16-byte field and shifted the embedded Mach-O, producing `unsupportedImageMagic(0xedfacf00)` in T20. Match the exact field width; slide-v5 fixtures also need valid page starts and chain links, not only a version header. |

| Core model or extracted helper depends on an app-only declaration | Audit actual target membership before compiling: CP8 scalar reading called CTypeHeaderParser from AnalysisModels+TypeDefinitions.swift, but the parser is outside MacScopeAnalysisCore. Keep primitive interpretation model-owned. CP7 topic helpers must be explicit AnalysisCore members and excluded from app recompilation; cross-file helper declarations need module-internal access, not file-private access. |

### Resource identity transition in retained native products (CP1b, 2026-10-13)

A new private source-identity receipt directory cannot attest an existing staged package unless its prior immutable staged receipt is supplied. Set MACSCOPE_NATIVE_PRIOR_RECEIPT_ROOT to the prior accepted directory; the stager admits that exact metadata-bound old copy and publishes the new identity only in the current directory. Missing/stale prior evidence stays a refusal; do not reverify the old package or clean retained products to conceal the gap. Native bridge cache and firstfailedstage receipts remain reusable.

`Scripts/dev_loop.sh` does this itself: `--native-verbose` registers its private root in `<DerivedData>/NativeIdentity.current`, and every later dev-loop run in that DerivedData (plain or verbose) uses shared-view mode with a fresh source-identity root and the registered root as the prior; a run that publishes a new staged receipt moves the pointer (`Scripts/qualification/dev_native_receipts.py`). A staged copy published before any receipt mode has no receipt anywhere and stays a refusal.

### Debug CP4 proof bookkeeping is not runtime provenance (CP1b, 2026-10-13)

NativeDecompilerBundleRuntimeAuthorityProvider admits a closed Debug schema. Keep native_decompiler_debug_cp4_supplement in the immutable external admission/proof record; emitting it as a runtime field causes buildEvidenceInvalid before any function admission. The receipt emitter excludes this field both from retained baseline evidence and fresh output. Preserve existing full-golden and supplement receipts; do not rerun them to repair metadata.

### Ordinary native acceptance must use an ordinary worker (CP1b, 2026-10-13)

MACSCOPE_NATIVE_DECOMPILER_LIVE_XPC_TESTING deliberately rejects unconfigured requests at enterNativeExecution before invoking the engine. Use an ordinary worker (empty MACSCOPE_NATIVE_DECOMPILER_LIVE_TEST_CONDITION) for ordinary native admission; signed lifecycle tests retain their configured live worker. The Debug continuation receipt explicitly binds ordinary mode to the empty effective condition and otherwise requires LIVE. Unchanged C++ golden/package evidence is reusable across this Swift-only mode change; never present lifecycle-barrier failures as constructor failures.

## Retained Release input admission
A native Release archive needs its actual Release build contract and first-consumer output metadata binding; retained Debug computation evidence alone is insufficient. Keep operational reuse fields outside the signed app provenance closed schema. A new copied package must use its own directory identity. Route receipt settings only for the explicit retained Release path, and refuse missing dependency reuse receipts before any fallback verifier. Native worker and AnalysisWorker bytes are admitted after embedding/signing; metadata leases protect publication without repeat hashes.

## Source Links architecture and multi-image fixture ownership (2026-10-18)

A binary's architecture display label can be `arm64` even when its selected header and dSYM identify `arm64e`; universal display text can also include container prose. Source Links uses `SourceLinkImageIdentity.architecture(for:)` to derive the precise name from loader-owned CPU evidence when present. Do not repair this mismatch by normalizing arm64 and arm64e together. The real-specimen source correlation witness covers this producer/consumer boundary.

When composing an engine-produced additional image in a native fixture, apply `AnalysisStableIdentity.restamp(_:to:)` and `snapshot.insertImage`, as `WorkspaceStore.loadAdditionalBinary` does. Engine function/symbol IDs are initially primary-slot scoped; directly appending another primary analysis can reach Save with duplicate `functions.uuid` values even though matching succeeded. Preserve the failure and correct fixture ownership rather than changing database uniqueness constraints.
