# Sandbox profile expansion

`SandboxProfileExpander.expand(profile:imports:entitlements:)` accepts SBPL text, a caller supplied map of import names to text, and entitlement keys. It performs no filesystem access. The app can provide text it has read through its existing file selection path.

The reader produces `Expression` values: symbol, quoted string, regex string (`#"..."`), or list, each with a one based source line and column. Comments and whitespace are discarded. `rendered` emits a canonical S expression for inspection and round trips. Regex literals retain their source contents verbatim. Input, token count, nesting, expansion depth, rule count, and total expansion steps have explicit limits. Exceeding the step or rule limit returns a partial report with `expansion limit` in `expansionCycles`.

Expansion first parses all supplied sources and collects function and simple value definitions, walking imports with cycle detection. It then walks the target profile in source order. Macro arguments replace parameter symbols in a macro body; nested calls are expanded with a call stack. `when` and `if` take a known Boolean branch for supplied entitlement keys. The walker flattens allow and deny declarations into deduplicated rules, unions the entitlement keys for duplicate declarations, and preserves their filter forms as text.

The Codable `Report` contains `effectiveRules` (decision, operation, raw arguments, and `unlockedBy` entitlement keys), `grantedNamedMachServices` (deduplicated direct `global-name` strings on allow `mach-lookup` declarations), `entitlementRules` (supplied key to rules associated with its positive gate), `unresolvedImports`, `unresolvedMacros`, `unresolvedConditions`, and `expansionCycles`. A supplied entitlement with no positively gated rule maps to an empty array. For a true `or` gate, attribution lists every true supplied entitlement in that disjunction; it does not prove that each was individually necessary to unlock the rule.

This is an expansion report, not a decision procedure for macOS sandbox enforcement. Missing imports and undefined macros are reported without invented rules. Unknown conditions produce no branch rules. Macro/import cycles stop at the cycle. Regex, subpath, `require-all`, `require-any`, metafilters, and other filter semantics remain verbatim; the report does not decide whether a path or service matches them. Deny precedence, implicit policy, dynamic parameters, and OS version behavior are not modeled. A listed allow declaration, including a named Mach service, therefore does not by itself prove that the running app can access it. The caller must not use this report as an authorization oracle.
